# Сэнди — бот рассылок для VK Teams

Сэнди — Python-бот для отправки информационных сообщений пользователям VK Teams. Бот собирает анкету пользователя, а администраторы создают рассылки с выбором аудитории по полу и возрасту. Данные хранятся локально в JSON-файлах, отдельная база данных не требуется.

## Возможности

- Регистрация: имя, пол и возраст; просмотр и изменение анкеты.
- Разовые рассылки: отправка в ближайший цикл планировщика или в заданную дату и время.
- Регулярные рассылки с ежедневным повторением.
- Отправка текста или файла, в том числе с подписью.
- Выбор получателей по полу и возрастному диапазону.
- Реакции 👍 и 👎 на разовые рассылки и статистика постов.
- Роли пользователя и администратора, команды управления администраторами.

Некоторые функции имеют ограничения в текущей реализации — они перечислены ниже.

## Структура проекта

| Файл | Назначение |
| --- | --- |
| `main.py` | Обработка сообщений и кнопок, регистрация, рассылки, планировщик и статистика |
| `user_data.py` | Чтение и запись пользователей и постов в JSON |
| `users.json` | Анкеты, роли и признак завершённой регистрации |
| `posts.json` | Очереди рассылок, отправленные посты и счётчики реакций |
| `TOKEN.env` | Токен бота в переменной `BOT_TOKEN` |

## Требования

- Python **3.12 или новее**: в `main.py` используются f-строки с повторным использованием двойных кавычек внутри выражений.
- Доступ к API вашего сервера VK Teams и токен бота.
- Пакеты `mailru-im-bot` и `python-dotenv`. Версии зависимостей в проекте не зафиксированы.

Библиотека, предоставляющая импорты `bot.bot` и `bot.handler`, устанавливается как `mailru-im-bot`. Инструкции по созданию бота через Metabot приведены в [документации библиотеки VK Teams Bot API](https://github.com/mail-ru-im/bot-python). Пользователь должен добавить бота в контакты или первым начать диалог, чтобы бот мог ему отвечать.

## Установка и настройка

### 1. Подготовьте окружение

Откройте терминал в папке проекта. Пример для Windows PowerShell без активации виртуального окружения:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install mailru-im-bot python-dotenv
```

Для Linux / macOS:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install mailru-im-bot python-dotenv
```

### 2. Укажите токен

Создайте `TOKEN.env` в корне проекта или заполните существующий файл:

```dotenv
BOT_TOKEN=your_bot_token
```

Код загружает этот файл через `load_dotenv("TOKEN.env")`. Также можно задать `BOT_TOKEN` в окружении процесса: существующее значение имеет приоритет.

Не публикуйте настоящий токен и пользовательские данные. Текущий `.gitignore` исключает только `.idea/`; `TOKEN.env`, `.venv/`, `__pycache__/` и файлы с персональными данными нужно исключить отдельно перед публикацией.

### 3. Проверьте адрес API

Сейчас в `main.py` клиент создаётся как `Bot(token=token)`, без явного адреса сервера. Если вашему развёртыванию VK Teams нужен собственный адрес API, укажите его при создании клиента:

```python
bot = Bot(token=token, api_url_base="https://<ваш-сервер>/bot/v1")
```

Это шаблон: точный URL получите у администратора VK Teams. Параметр описан в [исходном коде клиента](https://github.com/mail-ru-im/bot-python/blob/master/bot/bot.py). Отдельная переменная окружения для адреса API в проекте не предусмотрена.

### 4. Подготовьте хранилище

Для нового экземпляра создайте `posts.json` со следующей структурой, если файла ещё нет:

```json
{
  "planned_queue": [],
  "posts_queue": [],
  "sent_posts": [],
  "views": 0,
  "likes": 0,
  "dislikes": 0
}
```

Не заменяйте этим шаблоном файл с существующими рассылками. `posts.json` обязателен: при его отсутствии или некорректном JSON функция загрузки возвращает структуру без `planned_queue`, и запуск завершается с `KeyError`.

`users.json` создаётся при регистрации первого пользователя. Для пустого хранилища его можно подготовить вручную:

```json
{
  "users": {}
}
```

### 5. Запустите бота

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe main.py
```

Linux / macOS:

```bash
.venv/bin/python main.py
```

Запускайте программу из корня проекта: пути к токену и JSON-файлам относительные. Бот получает события через polling и работает, пока запущен процесс. Для остановки нажмите `Ctrl+C`.

## Первый запуск и команды

Откройте личный диалог с ботом в VK Teams и отправьте `/start`. Бот попросит имя, пол и возраст. Первый пользователь пустого хранилища автоматически получает роль администратора; остальные регистрируются как обычные пользователи.

| Команда | Назначение |
| --- | --- |
| `/start` | Начать регистрацию или получить приветствие |
| `/info` | Посмотреть анкету; администратору также показывается список команд |
| `/broadcast` | Создать разовую рассылку — требуется роль администратора |
| `/planned_broadcast` | Создать ежедневную рассылку — требуется роль администратора |
| `/remove_planned_post` | Показать регулярные посты и запросить номер для удаления из очереди |
| `/level_up` | Начать назначение администратора — требуется роль администратора |
| `/level_down` | Начать снятие роли администратора — требуется роль администратора |
| `/get_statistics` | Посмотреть общие счётчики и посты с максимальными показателями — требуется роль администратора |

Для изменения анкеты нажмите «Изменить» под сообщением `/info`. При изменении роли бот запрашивает почту пользователя: введённая строка должна совпадать с ключом уже существующего пользователя в `users.json`.

## Создание рассылки

1. Отправьте `/broadcast` для разовой рассылки или `/planned_broadcast` для ежедневной.
2. Пришлите текст либо файл с необязательной подписью.
3. Введите `now` или дату и время в формате `dd.mm.yyyy hh:mm`, например `31.12.2026 14:30`.
4. Выберите пол получателей: «Муж», «Жен» или «Все».
5. Укажите возрастной диапазон, например `14-99`.
6. Проверьте предпросмотр и нажмите «ДА». Кнопка «НЕТ» отменяет создание поста.

Границы возраста **не включаются**: диапазон `14-99` соответствует возрастам от 15 до 98 лет. Время берётся из локальных настроек компьютера, на котором работает бот.

Планировщик проверяет очереди примерно каждые 30–60 секунд, поэтому `now` означает отправку в ближайший цикл проверки. Ежедневный пост после обработки переносится на следующий календарный день с тем же временем. Бот должен оставаться запущенным для выполнения рассылок.

Для прекращения ежедневной рассылки отправьте `/remove_planned_post` и введите показанный номер поста. Нумерация начинается с **0**. Уже отправленные сообщения команда не удаляет.

## Реакции и статистика

Разовые рассылки содержат кнопки 👍 и 👎. Для каждого поста учитывается только первая реакция пользователя; изменить её повторным нажатием нельзя.

Поле `views` в этом проекте означает число уникальных пользователей, нажавших кнопку реакции. Это не счётчик прочтений сообщений в VK Teams. Регулярные рассылки отправляются без кнопок реакций.

Команда `/get_statistics` выводит общие счётчики и посты с максимальным числом просмотров, лайков и дизлайков. В текущей реализации вывод может завершиться ошибкой, если для какого-либо показателя нет поста с ненулевым значением.

## Особенности текущей реализации

- Планировщик запускается после подтверждения рассылки. При перезапуске программы сохранённые очереди загружаются, но автоматического запуска планировщика нет.
- `/level_up` и `/level_down` меняют роль только в загруженном объекте, без записи через `write_data()`. Изменения не сохраняются в `users.json`.
- В обработчике `/remove_planned_post` нет проверки роли администратора.
- Черновик рассылки выбирается как последний элемент общей очереди. Одновременное создание постов несколькими администраторами может привести к изменению чужого черновика.
- Черновики и готовые разовые посты находятся в одной очереди, без отдельного признака подтверждения. При уже работающем планировщике полностью заполненный черновик может быть отправлен до нажатия «ДА».
- JSON-файлы перезаписываются целиком, без блокировок между обработчиками и планировщиком. Одновременные изменения могут привести к потере данных; запуск нескольких экземпляров с общими файлами не предусмотрен.
- Состояния диалогов хранятся в памяти и теряются при перезапуске.
- Ошибки отправки отдельным получателям пропускаются, а пост может попасть в `sent_posts` даже при неудачной доставке. Наличие записи не гарантирует получение сообщения всей аудиторией.

Эти пункты описывают фактическое поведение кода и должны учитываться при использовании бота.
